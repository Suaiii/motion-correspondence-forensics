## 目标与读取顺序

按 [共享工作计划](../../research-plan/WORK_PLAN.md) 完成数据验收、算法实现、实验、分析和论文证据整理。每次开始读取根目录 AGENTS.md、共享计划、任务表、最新 DEVLOG 及当前实验协议，并检查已有产物，避免重复运行。

任务表的 ready 仅表示已登记依赖可供选择；执行前还要核对实际证据、requires_pass、剩余预算和服务器状态。历史硬件检查不证明服务器现在在线。

## 工作职责

- 维护科研代码、实验配置、输入清单、日志、checkpoint、逐样本预测、图表源数据和实验报告。
- 先满足来源、祖先分组与实际采样条件，再筛查机制；通过机制门槛后才扩大训练。
- 优先复用已核验的原视频、DINO 权重和缓存。新增协议须重新核对缓存配置，不能因名称相似而直接复用。
- 当前主候选为经匹配扰动校准的局部对应可组合性；已有 actual-lag 与 local-rank 工具作为诊断和对照保留。
- 按共享计划 3.5 节保留静态重复帧及同六帧静态 patch 基线；非零 JS/响应不是时序异常的充分证据。软件 gate 的 pass 不得描述为真实数据机制通过。
- C的软件定义仍绑定v1.2，DX03软件和DX04既有元数据描述范围已验收；当前v1.3只更正证据来源与状态。按3.6节保留同三帧与语义输入，按3.7节区分归档best-effort时间和原生整数PTS/time_base；新采集、数据验收与训练分别放行。
- 按预先定义的失败条件结束候选筛查，保留负结果，不在同一开发审计上无限调参。
- 服务器访问阻塞时推进文献、协议、合成验证和代码准备；依赖远端数据的任务如实保留阻塞。

## 科学与资源约束

软件测试、开发性能、机制支持、正式外部确认分别报告。均值种子 AUROC 与先集成概率再算 AUROC 不可混用；祖先未知不能用文件名唯一或哈希不同代替独立性。

最终测试集不参与选择模型、阈值、分数方向或论文报告规则。样本数不足时报告实际数量，不能复制补额。指标改善必须超过相同输入、容量与增强的对照。

遵守项目累计 6000 元和初始累计 180 GPU 小时约束，先核减历史实付和已用时数。仅操作已有授权实例；新增购买仍按实际授权处理。大数据和训练留在服务器，本地不保存凭据。

个人 19:30—22:00 工作时段不是服务器实验时限。已定义批次应完整执行并保留恢复状态，完成后同步紧凑结果、核验哈希，再按既定生命周期安排停机；不能把 GPU 空闲当成停止计费。

## 每项交付的最小内容

1. task_id、plan_version、代码版本及所依据的实验协议。
2. 可否证假设、数据角色、来源/祖先划分、采样与处理顺序。
3. 实际运行内容、模型选择方式、指标定义与统计方法。
4. 观察结果、支持程度、失败案例、限制；分别给出执行状态和建议 gate_result。
5. 证据路径、配置/清单/checkpoint 哈希、逐样本预测位置。
6. 实测资源消耗、账单是否已核对、当前实例状态的观测时间。
7. 下一步建议、尚缺依赖及需要用户动作的具体内容。
