## 冻结取帧与指纹

每条视频按已归档的原生帧总数 N，选择 index 0、floor((N-1)/2)、N-1。文件 SHA 重新核对；FFmpeg 当前选择帧输出的 integer PTS/time_base 与锁定值逐项比较。此处仅仅新核验三锚点，不声称重新完整 ffprobe 全部原生时间轨迹或独立重数每条视频的全部帧。实际维度、原生 index、PTS/time_base、RGB SHA 和维度绑定 RGB SHA 均留在指纹记录。无旋转、无模型、无音频特征，帧留在 RAM。

普通 CPU dHash 使用 RGB→灰度、Pillow BOX 缩放至9×8、逐行相邻像素 left>right 共64位。固定全帧和中心正方形两视图。9×8灰度标准差≤5，或64位1数<4/>60，标记低信息量。阈值在任何候选分数前锁定：单锚点任意视图距离≤4，双方均需有信息；视频三锚点对应距离均≤8，至少两个对应锚点均有信息，双方需有三个不同原生 index。

## 预检与固定控制

五池各取最小 SHA4条，再用固定盐化 SHA 补至24条，24/24完成，wall=7.191s，CPU=10.596s；另保留已知坏片哨兵，未替换原24条。线性全量预估 44.93min。实际全量批次 wall=73.98min，未重启或更换有利子集。

Bv2四个固定 parent，各有identity、CRF32转码、384缩放输出，共12固定阳性对。4/4 identity的三锚点 native RGB 完全相同；对应首帧阈值4命中 10/12；三锚点阈值8命中 6/12。6个不同声明parent对，在对应单锚点和三锚点均无命中。

非identity控制有自己的有限时间窗口，父视频首中末与输出首中末可能不对齐，缩放有letterbox；控制失败保留，阈值没有调到通过。因此不能把本次筛查解释为所有重编码、缩放、剪辑关系的完全召回。不同parent控制仅仅使用已有声明关系，不证明其全局祖先独立。

按冻结的两视图、任意单锚点与低信息规则完整判定，固定阳性12对中单锚点命中 10/12、三锚点命中 6/12；6个不同声明parent对均无命中。完整规则回执为 CONTROL_PROTOCOL_RECEIPT.json。原全帧距离回执仍保留；失败没有调阈值或删样。

## 搜索覆盖和候选

全池均纳入包内及跨包比较，没有按real/fake或原角色限制。单锚点64位分成5个不重叠块，阈值4以内必有至少一块相同；候选逐个精确计算Hamming。三锚点以中间帧9块覆盖阈值8，再核算全部三锚点与信息量要求。固定560个合成向量的独立穷举 oracle 与索引集合完全一致；该检查仅仅证明有限算法实现覆盖。

共 626 个视频候选pair：单锚点候选 587，三锚点视频候选 96，其中仅单锚点 530。跨包 318，包内 308；跨原角色 362，其中包内跨原角色 71；跨标签 187，同标签 439。

完整候选队列记录左右SHA键/池/角色、实际距离、对应anchor和view、原隔离与既有关系比较。每个单锚点视频pair至多保留4个命中实例及完整命中数量，所有实例可从紧凑帧指纹复算；多锚点视图最多4组。低信息量单帧没有扩成疑似祖先pair，另存精确RGB复用组和低信息量组的全部成员列表。既有组边、源键、A4命名线索闭包仍优先保留，视觉无命中不删边。

## 用法与限制

- 候选仅进入人工或不同执行者复核，不自动合并、不修改正式split，不升级真正祖先关系。
- 三个离散锚点会漏掉任意时间移位、部分剪辑和锚点间的单帧复用；中心正方形仅仅覆盖一种裁剪，翻转、任意crop和色彩变化未全面搜索。
- dHash相似也可能来自通用布局、静态场景或生成图像；低信息组和相同黑帧均不能证明同祖先。
- 解码异常隔离和失败记录保留8998分母，不视为视觉无重复。
- 未命中不能签全局无泄漏，也不能证明相机、生成器机制或预训练独立。公开描述性开发证据的使用仍受原协议/rights/QC与统一组规则限制。
- 所有数据保持开发/已暴露角色；final_confirmation、模型训练、GPU与机制gate均未释放。

`INPUT_LOCK.json`、`REFERENCE_LOCK.json`、`SEARCH_SOURCE_LOCK.json`与`PROTOCOL.json`绑定输入及源码；`selection.jsonl`绑定8998队列。`screen.py prepare/preflight/full`、`discover.py controls/search`提供独立源码；已有完整产物冻结后禁止重跑覆盖，仅仅复核读只读输入与结果。

准备阶段两次字段形态异常在任何像素/候选运行前修正，原始startup/protocol/code和异常回执保存于prepare_attempt001/002。正式选样和取帧protocol只冻结一次，正式CPU批次未重启。

大于32MiB的JSONL仅仅采用无损gzip保存，具体物理文件和完整行数见OUTPUT_FORMATS.json；不删减候选。序列化每128行检查namespace容量，保留安全余量。此I/O补充在任何全池候选分数产生前冻结，像素、锚点、阈值与索引逻辑不变。
