## 0. 一页结论

1. **最大的问题不是缺少努力，而是证据对象错了。** 171 个任务中 56 个 done/fail，GPU 试点（AL132–AL146）
   反复在同一 122 条样本、同一 DINO 张量上更换 LIF/事件编码。更根本的是，**现有全部三个数据池仅凭容器元数据
   就能以 AUROC≈1.0 区分真假**（见 §2），而且两个真实来源之间比真假更容易区分（0.985 vs 0.958）。
   在这样的数据上，任何“新机制”的正结果都无法与来源/格式识别区分，负结果也无法归因到方法本身。
2. **纯“评测分析”论文不足以冲 CVPR 主会。** 格式/时长/帧率捷径已被 VidAudit（2606.31004）、
   Michels et al.（2607.00948）、Real Data Lies（ICML 2026）、VidGuard-R1（ICLR 2026）覆盖；
   主会接收的同类工作都是“诊断 + 建设性修复”（B-Free CVPR’25、Aligned Datasets ICLR’25 等）。
   评测分析降级为本文的动机与协议部分。
3. **推荐主线：生成阶段反事实阶梯（Generation-Stage Counterfactual Ladder，GSCL）。**
   - 对同一真实视频，分别只替换 VAE 解码、部分去噪（不同强度）、运动生成（首帧 I2V），
     并把容器/时间/分辨率/码率与原视频逐项对齐。
   - 用它回答一个尚无人系统回答的问题：**可迁移到未见商用生成器的证据究竟来自哪一生成阶段？**
   - 同时据此给出训练范式。
   - 已发表的视频对齐工作（WaveRep NeurIPS’25、G2VD 2607.04607）只做到 VAE 重建；
     去噪/运动层级的真实锚定反事实训练，在调研中未检出。
   - 新颖性风险评为**中**，并非无风险，§3 给出证据与差异。
4. **决策方式改为阶段门 + 预注册淘汰标准 + 连续减半筛选 + WIP 上限。** 第一个硬门在 **10/23**：
   300 个锚点的试点若显示去噪/运动层级不优于 VAE-only，立即转入预定的退路（§8），不再追加同族变体。

## 2. 今晚两项实测（CPU、只读、可复算）

报告与哈希：[REPORT.md](../experiments/meta_shortcut_probe_20261016/REPORT.md)。

**E1 仅元数据可分性**（10 个容器字段，GBDT，5 折分组 CV）：

| 数据池 | 全元数据 AUROC | 最强单特征 |
|---|---:|---|
| RoboVid-SM（当前训练池） | 0.9996 | width 0.998，fps 0.997 |
| AEGIS Hard Test（当前外部测试） | 0.9998 | duration 0.854 |
| AIGVDBench 扩展（Luma/Pika/Vidu vs OpenVid-HD） | **1.0000** | **width 单特征 0.992** |

即使 AIGVDBench 统一了 H.264，分辨率仍完全泄漏标签。

**E2 冻结 DINO 特征上的对照：**

| 对照 | AUROC |
|---|---:|
| AEGIS 真实 DVF vs 真实 YouTube | **0.985** |
| AEGIS 真 vs 假（池内） | 0.958 |
| Vript 真实 ≥29fps vs ≤25.5fps | 0.612 |
| Vript 真实 720p vs 其他 | 0.538 |

**结论：**

- 现有池上，“检测真假”与“识别采集来源/格式”无法分开。
- 任何主结论必须同时满足：
  - 在**元数据不可分**（探针 ≤0.60）的协议下成立；
  - 逐真实来源报告结果，并给出 real-vs-real 下限。
- E1 的脚本可直接作为后续“格式规范化”工具的**验收测试**。

### 3.1 各候选方向的新颖性

| 方向 | 最近邻 | 判断 |
|---|---|---|
| 纯捷径诊断/评测分析 | VidAudit（帧数探针≈1.0→审计后 0.529）[V]；Michels（D3 fps 修正后 0.973→0.799，去偏集 0.48–0.54）[V]；Real Data Lies ICML’26 [S]；Fake or JPEG（仅 workshop）[V] | **高风险**。剩余空白（码率/GOP/PTS/VFR/H.265/平台链/real-vs-real 下限）只够一节或一张表 |

| DINO 轨迹/二阶差分 | ReStraV NeurIPS’25、D3 ICCV’25、STALL CVPR’26、SPLIT ECCV’26、RIFT MM’26 [V] | **高风险**，且被 Michels 证明部分依赖 fps/时长 |

| **去噪/运动层级的真实锚定反事实训练** | DIVID（SVD 首帧 I2V，2024，小规模，DIRE 特征）[S]；RA-Bench（仅评测：首帧 I2V 使 7 个检测器均值 AUC 33.4%→50.9%）[S]；VideoDiffusion（ACM，RAVE 语义配对）[S]；B-Free（图像）[V] | **中风险**。未检出“按生成阶段分层 + 容器对齐 + 迁移剂量反应”的工作 |

### 3.2 GSCL 相对最近邻必须写清的四点差异

（W0 由第一类工作逐篇精读确认，见 §9 的 T1.2。）

1. **阶段分解。** WaveRep/G2VD 只替换 VAE 解码。GSCL 依次只替换解码 → 去噪（强度 s）→ 运动，
   测“哪一层证据可迁移”的剂量反应。这是测量结论，不依赖方法一定变好。
2. **容器逐项对齐。** 每个反事实继承锚点的物理时长、fps、帧数、分辨率、编码器/CRF/GOP。
   真实锚点经过同一次最终编码，格式通道在构造上被关闭；WaveRep 只统一 H.264。
3. **时间证据需要时间反事实。** WaveRep 作者承认帧级模型漏掉时间伪影；Michels 显示运动类检测器去偏后接近随机。
   GSCL 预测：时间头的增益只在运动被重新生成的 rung 上出现。这是可证伪的交互假设。
4. **传播链。** 本项目已有原生 PTS 与 OSN/WeChat/WhatsApp、CRF、缩放、时间重采样处理链，
   G2VD 未测 H.264，WaveRep 在 CRF32 时 bAcc 降到 59。

## 4. 主线：生成阶段反事实阶梯（GSCL）

### 4.1 研究问题与假设

- **H0（协议有效性，必须先过）：** 规范化后，元数据探针 AUROC ≤0.60 且分组 CV 稳定；
  real-vs-real 下限逐池报告。不过则一切效果比较无效。
- **H1（阶段迁移）：** 以去噪层级（R1/R2）或运动层级（R3）反事实训练，比只用 VAE 重建（R0，即 WaveRep/G2VD 配方）
  在未见商用生成器上的 macro AUROC 高 ≥0.03；祖先簇配对 bootstrap 95% 下界 >0；≥4/5 种子为正。
  **若所有 rung 与 R0 相差在 ±0.02 内，H1 被否证。**
- **H2（时间证据的条件性）：**
  - 预测：时间头相对帧均值头的增益，只在 R2/R3 上显著，而在 R0 上不显著（rung × 头的交互）。
  - 否证：无交互，或在 R0 上同样出现。
- **H3（传播稳健性）：** 在 H.264/H.265 CRF28/32、缩放、OSN/WeChat 链下，阶梯训练模型的 AUROC 下降，
  比 R0/WaveRep 少 ≥0.03。

### 4.2 阶梯构造（每个真实锚点 x）

| rung | 生成操作 | 保留 / 替换 |
|---|---|---|
| R0 | 官方完整版视频 VAE 编码-解码（Wan2.1 VAE；CogVideoX VAE） | 只替换解码痕迹（复现现有配方） |
| R1 | SDEdit 式部分加噪-去噪，s≈0.3（Wan2.1-T2V-1.3B V2V；第二族 CogVideoX） | 纹理/高频由去噪器重写 |
| R2 | 同上，s≈0.6 | 运动被部分重写 |
| R3 | 锚点首帧 + 锚点字幕的 I2V（Wan2.2-TI2V-5B 或 CogVideoX-5B-I2V） | 外观锚定，运动完全生成 |
| R4（可选） | 锚点字幕 T2V | 仅语义配对（对应 AIGVDBench/WaveRep 的配对方式） |

**所有 rung 与真实锚点经过同一个“对齐到锚点”的最终编码：**

1. 按锚点原生 PTS 做物理时间重采样；
2. 统一分辨率/裁剪；
3. 统一编码器、CRF 与 GOP，并去除元数据。

种子、提示、步数、checkpoint 哈希逐条记录。

| 角色 | 数据 | 说明 |

### 4.4 检测器与对照

| 类别 | 内容 |
|---|---|

## 5. 可迁移的前沿决策机制（以及在本项目中的具体用法）

| 机制 | 来源 | 本项目用法 |
|---|---|---|
| 阶段门 + 预注册硬淘汰标准（go/kill/rework） | Stage-gate；AI Scientist v2 实验管理器的四阶段停止规则 | G0–G3 四个门，标准写在 §7；门前冻结、门后不改标准 |
| 连续减半（Successive Halving/ASHA） | Hyperband、ASHA | 第一轮 7 个筛选臂 × 300 锚点 × 1 种子 → 保留 3 个 × 1,000 锚点 × 3 种子 → 保留 1 个，加 R0 对照做全量 5 种子 |
| GPU 队列按信息价值排序 | VOI；Snoek 等的代价感知 BO（排序公式为本计划自定启发式） | 排序分 = P(成功) × 效应 × 主张权重 ÷ GPU 小时；GPU 不空转，CPU 审计只在 GPU 忙时插队 |
| 先写后做（PR-FAQ、摘要、空表） | Amazon Working Backwards；Peyton Jones | D0 当天写摘要、Figure 1 草图、四张空主表；**每个任务必须对应某个表格单元或主张 ID**，否则不立项 |
| WIP 上限 + 只由人补充队列 | Kanban 指南 | GPU 道：1 个运行 + 2 个排队；agent CPU 道 ≤2；**删除“队列不得为空”规则**；审计类任务 ≤20% 工时，只在事故后或门前触发 |
| 事前验尸（pre-mortem） | Klein（HBR 2007） | 10/19 前与导师 30 分钟：假设 11/17 失败，列原因，转成 §10 的风险与对策 |
| 抗篡改评测、只读原始日志 | METR 关于奖励破解的报告；MLR-Bench；Lossfunk 案例 | 评测器只读并记录哈希；第一类工作只看原始预测与日志生成的表，不看 agent 写的总结 |
| 显式失败上报 | Anthropic 多 agent 系统经验；silent-failure 研究 | 执行器鉴权/额度故障 1 个工作小时未解决 → 通知用户；里程碑滑期 ≥2 天 → 通知导师 |
| 锦标赛排序 + 多角色模拟审稿（仅作分诊） | AI co-scientist（Elo）；Agentic Reviewer（Spearman 0.42）；ReviewerToo | 每周对候选做一次两两比较，只用来排序；10/30 与 11/12 用 3 个审稿角色 + 1 个元审稿生成“缺失基线/消融/无支撑主张”清单；**go/kill 由人决定** |

## 8. 退路（预先写定，到门时执行，不临场谈判）

  或 IEEE TIFS（CCF-A 期刊）。
- **F3（算力或时间不够）：**
  - 先砍 R2 与第二生成族；
  - 帧数降到 17–33 帧、分辨率 480p；
  - 若有可用的步数蒸馏 LoRA，优先使用（需确认许可与效果）。
- 在任何退路下都不在同一张量上追加 LIF/事件编码变体；SNN 不进入主线（计划原文已将其定为可选结构）。
