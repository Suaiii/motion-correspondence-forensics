# AL13：同解码反事实评估合同

版本AL13-v1，2026-09-19，planagent；配合AL12设计审查。
本合同未生成/读取视频、下载权重或执行模型，不是数据库存或真实协议验收。
它规定后续候选必须回答的问题，方法与预算通过后才允许另派媒体批次。

## 1. 研究对象与标签分开记录

固定编码器E_D和解码器D的检查点、数值及调用配置。设C为可追溯摄像来源，
G_D=D(z_gen)为可追溯的完整生成样本，R_D(X)=D(E_D(X))。

| arm | 内容来源属性 | 解码处理链 | 角色 |
|---|---|---|---|
| C | camera_source | 原始已知导出；D处理次数0 | 原始摄像参考 |
| R | camera_source | R_D(C)，D处理次数1 | 摄像来源的VAE处理反事实 |
| R2 | camera_source | R_D(R)，D处理次数2 | 摄像来源的再次重建响应 |
| G | fully_generated | D(z_gen)，已确认D处理次数1 | 完整生成参考 |
| G2 | fully_generated | R_D(G)，已确认D处理次数2 | 生成来源的再次重建响应 |

来源属性不因VAE处理自动改变。R/R2是机制对照，不证明其像素未经生成式修改，
也不自动决定所有外部“AI内容”基准的标签。当前问题保持生成来源与处理痕迹两轴分离。
若候选把这些臂纳入监督训练，须在新候选准入时固定origin-target定义和各臂训练标签；
不得临时把误报的R改为fake来通过门槛。mixed/unknown、编辑生成、来源不明项目单列，不塞入二分类主表。

本表的次数仅用于已验证的所研究D处理链；历史编码、其他VAE或插帧另记，
未知处理史保持unknown，不能填0或从模型名称猜测。G来自哪个decoder/checkpoint必须有来源证据。

## 2. 配对、内容与处理效应

真正的同祖先配对为C→R→R2以及G→G2。R与G共享D仍不是同内容/同祖先反事实。
两者之间需预声明内容/条件/运动强度、输入时点、帧数、时长和空间支持匹配，
报告匹配前后覆盖与来源探针；匹配本身不保证消除所有混杂。

令s为冻结的同一个读出：

    delta_camera,D = s(R2)-s(R)   # 同摄像祖先，一次到两次D处理
    delta_generated,D = s(G2)-s(G) # 同生成祖先，一次到两次D处理
    delta_first,D = s(R)-s(C)     # 零次到一次，单列

delta_generated与delta_camera的分布比较可以检验所定义的响应差异。
两类祖先不同，二者之差不自动成为生成来源的因果效应。处理次数相同也不能排除
E_D编码分布、条件输入、首帧裁剪、缓存、时空平铺或原始媒体历史差异。
每个臂使用同一最终传播路径A：A(C)、A(R)、A(R2)、A(G)、A(G2)。
必须固定先重建后A，不能某类先压缩再重建、另一类相反。

## 3. 必要元数据字段

| 字段组 | 必须记录的字段 | 缺失处理 |
|---|---|---|
| 唯一身份 | artifact_id、arm、parent_artifact_id、root_origin_id、内容哈希 | 无法建祖先链者不进入主比较 |
| 来源 | origin_type、原始数据集/版本/使用条件、生成器及版本、条件素材哈希 | unknown不得改写成独立真实或完整生成 |
| 祖先/条件 | visual_ancestor_ids、参考图/视频、共同生成种子或复用输出、ancestor_component_id | 图连通组重算；共享视觉素材合并 |
| 方法版本 | encoder/decoder检查点哈希、配置/源码commit、导出入口 | 仅家族名称不满足“同D” |
| 数值调用 | dtype、latent缩放/平移、posterior_mean或sampling、随机种子、平铺/分块/缓存规则 | 未统一则分层报告，不能当相同处理 |
| 处理链 | 有序transform_chain、逐步输入/输出哈希、已知D次数、其他已知处理与unknown标记 | 处理顺序/次数不明者退出机制主比较 |
| 时间 | 原生整数PTS/time_base、时间字段来源、原帧索引、选帧规则、实际间隔、重复/缺帧 | 不用标称FPS/best-effort静默替代 |
| 输出时间 | output_clock_policy、与输入时间窗的声明关系、导出裁剪/长度变化 | 不把声明播放时钟当逐像素物理对应真值 |
| 空间与支持 | 原/输入/输出尺寸、共同crop、边界距、有效mask、coverage_reason | 相同规则剔除，报告各类/来源排除率 |
| 传播 | codec版本、GOP/帧类型策略、码率或质量值、缩放/插帧参数、pipeline哈希 | 同分布施加，不依标签选择 |
| 数据角色 | fit/calibration/development/heldout、exposure_log、origin_target_label、processing_attribute | 暴露过的样本不得重新命名为最终集 |
| 资源与证据 | 实际命令/环境、开始结束时间、计费与GPU使用来源、日志/预测/模型哈希 | unknown不填0，reserved不写实付 |

新VAE输出具有自己的导出PTS；不能假称它沿用了摄像传感器的原始时间戳。
要比较相同时窗，应保存外部声明的时间网格/裁剪合同及实际输出检查，
不声称非线性解码后的每个像素与原帧存在已证明的物理一一对应。
长度、首帧和cache规则按实际调用路径验收，AL09已说明不能只从一个helper推断整个导出。

## 4. 划分与泛化的三个轴

先将全部C/R/R2、G/G2及传播版本按视觉祖先连通组划分，再构造反事实。
若G使用C的图像/视频为条件，应将两条链合并；仅共享文字提示不自动等同视觉祖先，仍需记录。
所有派生臂继承祖先划分，不允许R用于训练、C用于测试，或G与G2跨划分。

- 未见generator：训练未使用该生成模型，但可能共享decoder，必须披露。
- 未见decoder：完整留出decoder家族/检查点及其重建臂，不能只留出生成模型名称。
- 未见真实source：校准与测试的摄像来源分离，内容/处理支持仍须验收。

单独和联合留出分别报告，不能把其中一种包装成其他两种。
同祖先配对区间以祖先组重采样，所有臂共同抽样；不能用patch数或派生版本数增加独立样本数。
同一decoder上的条件统计与所有decoder宏平均分别列出，避免样本较多的decoder支配总分。

## 5. 比较矩阵与失败条件

| 比较 | 目的 | 能否支持/否决什么 |
|---|---|---|
| C vs R，同祖先 | 测D处理本身造成的响应 | 只能说明处理效应；不能作为完整生成判别成绩 |
| R vs G，同D且匹配支持 | 在共享一次解码处理下检验来源区分 | 若仅C vs G有效而此处失效，原结果可被解码处理解释 |
| R2-R vs G2-G | 比较相同新增重建的响应分布 | 若效应只由次数/路径差解释，关闭新增响应机制主张 |
| R2 vs G2 | 同两次处理的来源比较 | 检查再次重建是否保留所声称来源信号 |
| 原始与统一传播后的上述各项 | 检查传播和输入支持 | 未见传播下失败时不能称稳健；不得后验换阈值 |
| 留出decoder/source/generator | 检查迁移目标 | 共享D不能算未见D，来源探针解释的增益不能计为目标机制 |

所有方法共享原帧、反事实臂、条件字段权限及对齐规则，按训练/推断可用信息再分表。
强对照至少包含普通像素/特征重建误差、同全部帧静态统计、完整时序谱/自相关、
同数据增广的ERM/普通一致性、相同参数容量，以及已选择直接近邻的匹配协议。
原作者原生配置另列。若候选测试时需要E_D/D，须对未知D的可得性、额外成本和回退方案作明确约定。
不能给候选更多反事实或decoder身份，再把优势归为目标函数。

未来检测评估分别展示origin-target与processing-attribute结果，并报告R/R2误报、
coverage及失败组。正式五种子、祖先配对区间、macro/最差组/clean代价与未见传播门槛不变。

## 6. 最小批次草案：仅验收与性能测量

目标为2个已验收的摄像祖先（来自2个真实source）和2个已有生成祖先（每个对应一个已核实D），
总独立组数由真实祖先图决定，不能直接假定为4。摄像C分别通过两个D得到R/R2；
各G通过其自身D得到G2。按此组合最多形成2个C、4个R、4个R2、2个G、2个G2，共14个片段。
这是拟议规模，不是现存或已验收样本；不为本批另运行生成模型。

帧长/尺寸须由未来候选和实际VAE合法输入合同确定，不能承接已被拒绝的H-P0“65帧”作为新方法默认。
短片不补帧，不同臂不使用类别依赖裁剪。该批只验证时间/形状/缓存/祖先记录、耗时、显存和存储，
不报拟合后AUROC或据14个片段决定机制成立。所有大产物留服务器，本地仅紧凑清单/哈希/测量。

执行前必须具备：新的候选设计准入（不可把AL05原fail改成pass）、RS00实际额度/报价或明确本批额度、
两真实来源及祖先证据、原生时间与输出时间合同、检查点/使用条件、可续跑记录和已授权停机安排。
总成本估算按实际报价乘预演用量并加存储计算，未知报价/历史消耗不填0。
这些条件当前未齐备，因此本合同不构成媒体或GPU批次授权。
