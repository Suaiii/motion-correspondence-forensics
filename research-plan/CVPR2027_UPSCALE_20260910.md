# 资源与实验规模升级

依据：用户要求充分使用已租资源，并提高数据量与测试强度。当前实例已连接、部署并完成服务器端验证。

## 已验证资源与性能

RTX 4090 D 24 GB；容器配额16 CPU核、62 GiB内存；数据盘550 GB；实例费用由用户确认1.88元/小时。128核、503 GiB是可见宿主机资源，不是本实例配额。没有修改容器限制或使用未租用资源。

| 测试 | 实测结果 |
|---|---:|
| 100条历史视频串行预处理 | 311.8秒 |
| 同批100条，4进程预处理 | 81.8秒 |
| 同批100条，8进程预处理 | 52.6秒 |
| 同批100条，12进程预处理 | 50.1秒 |
| 小型残差网络，batch64合成训练吞吐 | 约1637 clips/s |
| batch64峰值已分配显存 | 3.64 GiB |

并行测试同时限制每个解码器和OpenCV为单线程，避免嵌套并发争抢配额。各并发组解码帧哈希、索引与PTS一致。GPU吞吐使用合成输入、不含数据供应，不能称为完整视频检测速度，也不能用于确定DINOv2大骨干的batch。

batch128和256分别约1343、1212 clips/s，低于batch64。以实测吞吐选配置，不以显存占满作为目标。

## 执行改动

- 新增`materialize`，将每个分支的float32残差预生成到NPY分片；训练直接读取，避免每轮重复warp。
- 新增`purge-materialized`，核验后仅清理派生分支缓存；原视频与RGB/光流缓存保留，训练活动时拒绝清理。
- 缓存和实时计算路径统一连续内存布局。首次v4测试发现布局导致约2.2e-6参数差异；v5及服务器GPU验证已确认修复，旧失败产物保留。
- 新版本为v0.1.3；本地与服务器的缓存输入、连续/中断训练参数和概率均通过逐位一致性检查。
- 服务器直连Hugging Face失败后，使用AutoDL官方学术加速恢复访问。代理凭据没有写入项目文件。
